Complete recording required before submission

A labeled rehearsal is provided to plan the sequence. It is a simulation of the missing integration, not a complete review-ready API demonstration.

  1. Show the same existing app in the developer portal, its sandbox configuration, selected products and scopes. Hide credentials.
  2. Start at this exact public website domain. Show access, visible legal links and the real preparation workspace.
  3. Show an actual authorization redirect, the sandbox app's consent screen, approval by its authorized test account and a secure callback. Never record codes, tokens or secrets.
  4. Return to the actual application and show the connected account identity using an implemented, appropriately scoped feature. Do not claim a profile API call if none occurs.
  5. Preview an original or rights-cleared video, edit its metadata, show validation and explicit upload consent.
  6. After separate approval for that exact sandbox transfer, show the real inbox initialization and media transfer, retaining a redacted transaction reference.
  7. Show the real status endpoint result. A transfer or inbox status is not proof of publication.
  8. For inbox upload, open the TikTok inbox notification and show the received item. If posting is separately approved, show the creator completing the post and verify the exact result.
  9. Demonstrate every requested product and scope and the cancellation/error path. Do not insert simulated success screens into the real flow.
